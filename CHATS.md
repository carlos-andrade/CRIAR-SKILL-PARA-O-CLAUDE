# Histórico de Chats — CRIAR SKILL PARA O CLAUDE

> Registo cumulativo das conversas e decisões deste projeto. Não apagar entradas anteriores; acrescentar novas entradas no final do ficheiro.

## Política obrigatória de registo

- Registar as respostas produzidas pelo ChatGPT nos chats relacionados com este projeto.
- Preservar conteúdo técnico, decisões, requisitos, conclusões, alterações e pendências.
- Organizar os registos por data e assunto.
- Acrescentar novas entradas sem substituir o histórico existente.
- Após cada sessão de trabalho, atualizar este ficheiro no repositório e verificar a gravação.
- Não declarar uma atualização como concluída sem confirmação do GitHub.
- Quando uma resposta extensa não puder ser reproduzida integralmente, identificar explicitamente o registo como resumo; não o apresentar como transcrição integral.

**Convenção do ficheiro:** `CHATS.md` (sem apóstrofo, para manter um nome simples e compatível com ferramentas e sistemas de ficheiros).

## 2026-11-02 — Configuração do projeto e regra de histórico

### Objetivo do projeto

Criar uma Skill profissional para Claude especializada no mini índice futuro da B3 (WIN), com análises verificáveis, reconhecimento dos limites dos dados e separação entre factos, inferências, hipóteses e desconhecidos. A Skill deverá ser modular, instalável, documentada e testada, sem promessas de ganhos.

### Decisões e esclarecimentos desta sessão

1. Foi esclarecido que a verificação solicitada pelo utilizador dizia respeito ao campo **Instruções** das configurações do projeto ChatGPT, e não à descrição pública do repositório GitHub.
2. A imagem das configurações mostrou o início das instruções do projeto, coincidente com o início do PROMPT-MESTRE. A imagem, por si só, não permitiu confirmar a integridade do texto completo nem a contagem de 7.999 caracteres.
3. O utilizador determinou que todas as respostas dos chats relacionados com este projeto devem ser guardadas no repositório, num ficheiro de histórico.
4. Foi adotado o nome de ficheiro **`CHATS.md`**. O histórico deverá ser cumulativo, organizado por data e assunto, sem sobrescrever entradas anteriores.
5. A gravação deve ser confirmada no GitHub antes de ser comunicada como concluída.

### Registo operacional

Este é o primeiro registo criado para formalizar a política de histórico. Não representa uma recuperação automática de todas as conversas anteriores do projeto. A partir desta entrada, as novas sessões devem ser acrescentadas ao ficheiro, preservando o histórico.
